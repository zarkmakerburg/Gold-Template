title: Custom Templates
description: What a custom template must satisfy before it can be added.
---

Gold-Template ships seventeen frozen core designs plus thirteen downstream custom designs. Adding another is possible, and the
contract it must satisfy is written down rather than discovered by breaking things.

> **Status:** the custom tier is in production. GoldApp currently ships thirteen custom
> designs (`gold` through `dashboardpro`) alongside the seventeen frozen core templates.
> This page documents the contract new custom designs must continue to satisfy.

## The tier model

Every template belongs to a tier:

| | `core` | `custom` |
|---|---|---|
| ships in the release | yes | optionally |
| **byte-locked** | **yes** | **no** |
| changeable | only via an explicit freeze update | at will, by its author |
| held to the runtime contract | yes | **yes** |
| held to the accessibility contract | yes | **yes** |

> **The only difference between a core template and a custom one is the byte lock.**
> Every runtime, accessibility and artifact requirement is identical.

A custom template is not a second-class template. It is a template nobody has promised
not to change.

## The runtime contract

A custom template must satisfy all of the following:

- **79 required hooks**, each exactly once.
- `validateLayout()` passes.
- The **boot runtime** is byte-identical to Row's.
- The **application runtime** is byte-identical to Row's.
- The **locale island** is byte-identical.
- **Exactly three `<script>` tags** — boot, locale island, application.
- **No fork of the shared application runtime.** Small downstream enhancement scripts are
  allowed only when explicitly isolated to a custom design and covered by build/runtime tests.

## Layout ownership

A template owns its own directory and its own DOM:

```
src/templates/<id>/
├── layout.html
├── tokens.css
├── base.css
├── layout.css
├── components.css
└── rtl.css
```

- A custom design may reuse a proven core layout/style contract when that reuse is explicit,
  tested and documented.
- Shared application runtime is expected; visual overrides must stay downstream and scoped.

## Accessibility

Every interactive element must clear **44px**, with no exceptions — buttons, links, tabs,
dialog controls and dropdown items.

## Artifact rules

- One **self-contained** file.
- **No remote assets, no external fonts, no network dependency.** Assets are inlined at
  build time.
- **Deterministic output.**
- Within the **280 KiB (286,720-byte)** hard ceiling.

## RTL

Persian and Arabic are first-class. Logical properties throughout, `dir="auto"` on
content whose direction is genuinely unknown, and no horizontal overflow at 320, 390, 430
or 1440.

## Branding

A template must not override subscription branding. Branding belongs to the subscription,
not to the design.
